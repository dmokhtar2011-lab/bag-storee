# ربط متجر حكاية بقاعدة Firebase

## 1. إعداد تسجيل الدخول

من Firebase Console افتح **Authentication → Settings → Authorized domains** وأضف نطاق GitHub Pages الخاص بموقعك، مثل `اسم-حسابك.github.io` (من دون `https://` أو مسار المستودع).

من **Authentication → Sign-in method** فعّل **Email/Password**. أنشئ حساب المالك من تبويب **Users**. قواعد الأمان في `firestore.rules` مربوطة بـ UID الذي زودتني به.

## 2. نشر قواعد قاعدة البيانات

1. افتح **Firestore Database → Rules**.
2. استبدل محتوى المحرر بالكامل بمحتوى الملف `firestore.rules`.
3. اضغط **Publish**.

القواعد تسمح للزوار بإرسال طلب صالح فقط، وتمنع قراءة بيانات العملاء إلا لحساب المالك المحدد في القاعدة. لا تحوّل القواعد إلى وضع الاختبار أو تسمح بالقراءة العامة.

## 3. تحديث ملفات موقع GitHub Pages

ارفع هذه الملفات الخمسة إلى جذر مستودع GitHub، ووافق على استبدال النسخ القديمة:

- `index.html`
- `checkout.html`
- `style.css`
- `store.js`
- `firebase.js`

اترك `firestore.rules` و`firestore-data-model.md` و`README-GitHub.md` في جهازك كملفات إعداد ومرجع. بعد **Commit changes** انتظر تحديث GitHub Pages، ثم افتح الموقع بعنوانه المنشور.

## 4. تجربة الربط

أرسل طلبًا تجريبيًا من الموقع، ثم افتح **إدارة المتجر** وسجّل الدخول بإيميل وكلمة مرور حساب المالك. ستجد الطلب في تبويب **الطلبات**. لا ترفع كلمة المرور إلى GitHub.

## ملاحظات

- صور المنتجات وإعدادات التصميم في النسخة الحالية ما زالت محفوظة محليًا في متصفحك؛ Firestore هنا يخزن الطلبات فقط.
- إعداد Firebase الموجود في `firebase.js` مخصص لتطبيق الويب، وهو ليس كلمة مرور. أمان البيانات تفرضه قواعد Firestore.
- احذف أي بيانات طلبات تجريبية بعد الانتهاء من التجربة.
